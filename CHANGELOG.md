# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- A directory of Claude Code extensions whose source URLs were checked: Anthropic's four built-in mods (`sec-default`, `diff`, `telemetry`, `agents-md`) from `anthropics/claude-code/mods`, plus real plugins, skills, agents, hooks, commands and MCP servers.
- A guide for every mod, written from its own README and source: what it does, how it works, set up, download the source (real sparse-clone commands), test it, and mod-specific sections. Pages have a table of contents and copyable command rows, and say plainly where the source is silent, for example on how to enable function hooks.
- An Ideas page at `/ideas/` for the eight mods proposed in the marketplace spec. They have no public implementation, so they live in `src/data/ideas.json` and never appear in the directory, its counts or its search.
- Community listings by pull request: one JSON file per entry in `src/data/community/`, validated at build time. Rules cover allow-listed copy-to-run commands, no control or bidirectional characters, publisher and repository owner identity, reserved names, similar slugs, no claimed stars or featuring, and no future check dates. Community entries carry a visible "Community listing" label.
- A catalog schema with availability (installable, built in, source only), a notice for caveats such as early access, labelled details, and a required guide for mods.
- `npm run catalog:verify` and `npm run catalog:structure` (with `--only`) to check that URLs respond and that plugin and mod entries have their manifest files, refusing hosts outside an allowlist and checking every redirect hop.
- A design system with light and dark themes, a landing page with live search, a browse page with URL-driven search, kind, category, availability and sort filters, detail pages for every entry, and Security, Publish and About pages that state what is and is not checked.
- Custom 404 page (kept out of search results), `sitemap.xml` and `robots.txt`.
- Vercel Web Analytics through `@vercel/analytics`. It is disclosed on the About page and only records page views once it is enabled in the Vercel dashboard.
- A brand kit: a rounded square in the accent green holding a `>_` prompt, with the wordmark "Claude Code Mods" in Geist. The mark is one set of shapes in `src/lib/seo/brandMark.ts` that draws the favicon, the icons and the share banner. It uses no Anthropic or Claude logo or mark. Files: a real multi-size `src/app/favicon.ico` (16, 32 and 48 px, built by `scripts/make-favicon.mjs` with no dependencies), a 32 px `icon.tsx`, a 180 px `apple-icon.tsx`, and a web app `manifest.ts` with 192 px, 512 px and maskable 512 px icons.
- Link previews: a 1200 by 630 Open Graph and Twitter banner (`opengraph-image.tsx`, `twitter-image.tsx`) with the tagline and an "Unofficial community directory" note, plus a generated image for every extension page and the Ideas page showing the kind, name, summary, publisher and a "Built in" or "Community listing" tag. Catalog text is clamped and rendered only as text. Geist and Geist Mono font files sit in `src/assets/fonts/` under the SIL Open Font License, with the license text beside them.
- One typed metadata helper in `src/lib/seo/` for every page: unique titles and descriptions, an absolute canonical URL with a trailing slash, Open Graph, Twitter cards, robots directives, author and creator, and an Atom feed link. Search console verification tags come from `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` and `NEXT_PUBLIC_BING_SITE_VERIFICATION` and are omitted when unset.
- JSON-LD structured data: WebSite with a search action and a publisher on the home page, a CollectionPage with an ItemList on Browse, a BreadcrumbList and SoftwareSourceCode on each extension page, and a WebPage with breadcrumbs on the other pages. It states only facts in the catalog, and `license` appears only for a recognised SPDX id. The serializer escapes `<`, `>`, `&`, U+2028 and U+2029 so community text cannot close the script element.
- `llms.txt` and `llms-full.txt` for AI search, following llmstxt.org: mods first, then the other kinds, site docs, and a clearly separate "Proposed ideas (not real, no public implementation)" section. Both are generated from the catalog.
- An Atom feed at `/feed.xml`, newest source check first.
- A Hooks page at `/hooks/`: a reference to every one of the 125 events in `src/data/events.json`, grouped by family (engine, calls on `$`, classic) and noun, with a filter by text and family. Each event links to the line that declares it in Anthropic's type declarations at the pinned commit and lists the entries in the directory that use it, including entries that reach it through a wildcard such as `classic.*` or write a classic event bare, such as `PreToolUse`, and says how. Hook names that select no event, such as `telemetry.*`, are listed apart. Every row is rendered on the server, so the page reads in full without JavaScript. It says what it does not know: it names events only and does not describe what an event does, and which entries use an event is as each entry's listing names it, not checked against its code. It is in the header and footer navigation, the sitemap and `llms.txt`.
- A read-only `/catalog.json` with the catalog and the page URL of each entry, plus a disclaimer that it is not a security review, that community text is data and that every command must be read before it is run. Anthropic and maintainer entries are complete; community entries are an index record built from an explicit allowlist of fields (name, kind, categories, summary, publisher, source URL, availability, hooks, verification), so a submitter's long text and copy-to-run commands are never published there, matching `llms-full.txt`. It is served as UTF-8 JSON with `Access-Control-Allow-Origin: *` (this path only), and is deliberately not a Claude Code plugin marketplace.
- `robots.txt` names the search and AI crawlers it allows (Googlebot, Bingbot, GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-User, Claude-SearchBot, PerplexityBot, Perplexity-User, Google-Extended, Applebot-Extended and CCBot).
- `sitemap.xml` gives every entry its own last modified date and a change frequency and priority, with mods ranked above other kinds. The Ideas page is included.
- A Deploy section in the README for Vercel.
- GitHub Actions: `validate.yml` (typecheck, lint, tests and build on every pull request, catalog checks on changed community files, and an advisory path check) and a weekly `reverify.yml` that re-checks every entry so link rot shows up as a failed run.
- `.github/CODEOWNERS`, a pull request template, an issue template for wrong or dead listings, and `CONTRIBUTING.md`.
- `src/data/events.json`: the 125 hook events of Claude Code's function hooks (38 engine events, 54 calls on `$` and 33 classic hooks), read from Anthropic's type declarations at a pinned upstream commit. It stores names, family and the declaring line only, because the declarations are published under "All rights reserved" terms; the site links to them instead of copying them. It is validated at load time, and a test checks that every event the Anthropic mods hook exists in it.
- `npm run sync:events` (`scripts/sync-events.mjs`) regenerates that file. It prints what was added, removed, moved or re-filed and writes nothing unless `--write` is given. It refuses any change in the declarations' layout instead of returning a shorter list, never builds a pattern from upstream text, and caps the download while reading it.
- A Learn section. `/learn/` says what a Claude Mod is, explains the five ideas behind function hooks and compares a mod with a plugin, a classic hook, an MCP server and a skill in one table. `/learn/getting-started/` covers turning function hooks on, a starter mod, and testing, validating and running it. Each idea and each row of the comparison links its source, and the pages say the commands were run on Claude Code 2.1.278 on 2026-09-21. The Getting started page warns that testing or loading a mod runs its code, scopes the enable variable to each command, starts from a clone of the repository, and lists what the starter's force push check misses. Both pages are in the sitemap, `llms.txt` and `llms-full.txt`, have a Learn link in the header and footer, and carry breadcrumbs that name Learn as the parent.
- A hook on an extension page that names exactly one event now links to that event's row on the Hooks page. Wildcards stay text.
- A Migration page at `/learn/migration/`: how a classic **command** hook maps onto a function hook (a classic hook can also be an HTTP endpoint, an MCP tool call, a prompt or a subagent, which this page does not cover). It says first that Anthropic publishes no guide for this move (the plugin-dev `migration.md` moves command hooks to prompt hooks, which is a different move) and is written from the type declarations and the hooks docs. It covers what changes, the two ways to move a hook (keep the classic event as `classic.<Name>`, or hook the engine event around it), a table of exit codes and JSON becoming returned values, the engine events the declarations relate to four classic events, a worked example from a shell script that exits 2, and the 33 classic events linked to their rows on the Hooks page. Every row names every source it rests on, and the last section names the commit the checks ran against and says how each part was checked and what was not.
- `templates/migration-example/`: three classic hooks (PreToolUse, Stop, UserPromptSubmit) as function hooks on the `classic.<Name>` events. The test kit has no call that fires a classic event, so the example has no tests: it is checked by `claude plugin validate` and by `npm run typecheck:templates`.
- `npm run typecheck:templates` (`scripts/typecheck-templates.mjs`) compiles everything under `templates/` against Anthropic's declarations, fetched at the commit pinned in `src/data/events.json` into a temporary folder and deleted afterwards, never written into this repository. A positive fixture with one hook for each kind of result the Migration page's table claims must compile, and eight negative fixtures must fail to compile (for example a `deny` returned from `classic.Stop`, or a write to the read-only event), so a change in the declarations that breaks a claim on the page fails the check. It runs `tsc` with an argument list and no shell, with a three minute limit and a memory cap, refuses a symbolic link under the folders it compiles (TypeScript follows a link into any file and quotes it in its errors), and removes the temporary folder even on Ctrl-C. It needs the network, so it is not part of `npm test` and does not run in CI; a maintainer runs it by hand, most often after `npm run sync:events` moves the pinned commit.
- `scripts/lib/fetch-capped.mjs`: the timeout, no redirects and byte cap that `sync-events` used, now shared with the typecheck script and unit tested.
- A section on `/security/`, "How Claude Code keeps a mod in check": the five seats a plugin can hold (prepend, user, append, builtin, core, outermost first), how side effects go through `$`, and that a hook which throws, overruns its time budget or answers a wrong shape is skipped rather than refused. It restates what Anthropic's declarations, the Mods README and the announcement say, says this site did not test it, keeps the seats apart from the proposed tiers A, B and C, and names the security mod only by its source repository, linking its own README.
- `templates/mod-starter/`: a starter mod, `block-force-push`, whose tests pass under `claude plugin test` (`npm run test:starter`). The Getting started page reads its files when the site is built, so the page shows the code that was tested. The folder is left out of the site's TypeScript project because it imports types that only exist inside Claude Code.
- `CodeBlock` and `ComparisonTable` doc components: file contents that scroll instead of wrapping, and a real table with a caption and row headers.
- A tutorials page at `/learn/tutorials/`: the 9 official videos from the announcement issue (anthropics/claude-code #91870), grouped Basic, Advanced and Case studies as the issue groups them, each with its caption quoted exactly, a duration, and, for the 2 videos whose caption names a real event or the `*` pattern, a link to its row on the Hooks page. The clips are not re-hosted: they play from Anthropic's own stable GitHub attachment URLs, the same ones the issue itself embeds, which keep working because GitHub reissues a fresh short-lived redirect on every request. The page says plainly that no captions or transcripts exist. Structured data adds one schema.org `VideoObject` per video, with an exact duration only where the issue states one (60 seconds for Basic and Advanced; Case studies are stated only as "around 2 minutes", so no exact duration is claimed for them).
- `vercel.json`'s Content-Security-Policy now allows `media-src` and `img-src` from `github.com` and the one GitHub attachment CDN host the tutorial videos use, by exact hostname, so the redirect chain the videos need is allowed without a wildcard. Verified in real Chrome against a local server that replays the same headers: the videos load real metadata under the policy with no CSP violation logged.
- Two prominent buttons at the top of `/learn/`, above the first section: "Watch the video tutorials" and "Build your first mod", so both are visible without reading the page's closing paragraph.
- The header's Learn link now opens a dropdown of its three subpages (Getting started, Migration, Video tutorials) on click, closing on Escape, an outside click or choosing a page; Learn itself still links straight to `/learn/`. The mobile menu lists the same three pages indented under Learn, always visible. `NavLink` gained an optional `children` field for this, one level deep, used only by Learn.
- A video showcase on the home page, between the featured mods and the install flow: the 4 Basic tutorial videos (a real filtered subset of the 9, not a hand-picked list), each a poster image and title that link to its exact clip on `/learn/tutorials/`. No video plays on the home page itself.

### Changed

- The Hooks page's event list is grouped behind one collapsed, native `<details>`/`<summary>` per family (Engine, Calls on `$`, Classic), closed by default instead of always rendering all 125 events open at once. Each family keeps its real heading in the outline whether open or closed. A link to a specific event, from the Migration page, an extension's guide or the tutorials page, still opens the right family and scrolls to the row: the browser does this natively from the row's existing anchor id, with no script of this site's own. Typing a filter or picking a family still switches to the flat, always-open list of just the matches, unchanged from before.
- The guides of the four Anthropic mods now say where the flag for enabling function hooks comes from: `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` is named in the Sep 9 update of the announcement issue (anthropics/claude-code #91870), not in any documentation, and may change. The issue is linked from each mod page, and the four entries were re-checked on 2026-09-21.

- The site deploys on Vercel, not Cloudflare Pages. `NEXT_PUBLIC_SITE_URL` defaults to `https://claudecodemods.com` in production builds, so canonical URLs and the sitemap never say localhost.
- Page titles and descriptions are rewritten for search: titles fit 60 characters with the site name, descriptions are 110 to 160 characters, and extension pages read "<name>, a <kind> for Claude Code".
- Nothing on the site claims a listing was reviewed or scanned. "Source verified" means the source URL responded on the catalog date, and the proposed security tiers are described as a design with no scanner.
- The four Anthropic mods are described as their README describes them: early access, shipped inside Claude Code, source published as built, and under "All rights reserved" terms, not open source.

### Fixed

- Sections that fade in as they scroll into view stayed invisible when they were taller than five windows. The wrapper waited for 20 percent of a section to be on screen, which a section that tall can never reach, so the whole event reference on `/hooks/` (over 12,000 pixels on a desktop and 16,000 on a phone) was blank however far you scrolled. A section now fades in as soon as any part of it is on screen. A test holds the setting, and a scroll check in a real browser confirmed that no section on any main page stays hidden at desktop and phone widths.

### Security

- Validation workflows run on `pull_request` (never `pull_request_target`) or on a schedule, with read-only permissions, no secrets, actions pinned to full commit SHAs, `npm ci --ignore-scripts`, and changed file names passed NUL separated. The community diff uses `--no-renames`.
- Link components reject any href that is not an internal path, an anchor or a plain https URL, and external links keep `noopener noreferrer`.
- Catalog URLs must be https, on an allowlisted host, with no credentials or custom ports.
- Security headers in `vercel.json`: a Content-Security-Policy, HSTS, `nosniff`, a referrer policy and a permissions policy. The site deploys on Vercel, so the earlier Cloudflare Pages `_headers` file is gone.
